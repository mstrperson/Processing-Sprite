Images

Swap your shapes for actual pictures.

When to use this: Any time after Lesson 4. It works well between Lessons 4 and 5, or between 7 and 8 when you are starting to make your world look polished. One period, standalone.

New idea: Loading and drawing image files   |   Builds on: Lesson 2 (extends Blob) and Lesson 4 (control). Nothing after this depends on it.

What you will be able to do

  • Add image files to a sketch using the data/ folder
  • Show an image as a sprite using ImageSprite
  • Put a PImage inside your own extends Blob character so collisions still work
  • Explain the difference between ImageSprite (for decoration) and an image inside a Blob (for the player)

New words

data/ folder — a special folder inside your sketch folder where Processing looks for images and sounds
ImageSprite — a sprite from the library that shows an image file instead of a shape
PImage — Processing's type for a loaded image. Think of it as a variable that holds a picture
loadImage("file.png") — the command that reads an image file out of the data/ folder
transparency — the see-through part of a PNG. Without it your character comes with a rectangle stuck to it

How it works

The data folder is where Processing looks

Processing will not find your image unless it is in exactly the right place: a folder called data inside your sketch folder.

Sketch → Show Sketch Folder. Make a folder called data (exactly that, lowercase). Drag your image in. Done — Processing finds it automatically.

PNG, JPG, and GIF all work. PNG is the one you want, because it can have a transparent background.

ImageSprite — for scenery

ImageSprite shows a picture and has all the sprite methods you already know: move(), setVelocity(), followMouse(), drawSprite().

  • But it has no collidesWith(). ImageSprite is not a Blob, so it cannot collide. Use it for scenery, not for things the player has to touch.
Three ways to size an ImageSprite
new ImageSprite(this, x, y, "tree.png")            // 100 x 100 pixels
new ImageSprite(this, x, y, "tree.png", 80)        // 80 x 80 square
new ImageSprite(this, x, y, "tree.png", 120, 80)   // 120 wide, 80 tall

For your player, put the image inside a Blob

Your player needs collisions. So instead of using ImageSprite, you keep extends Blob — exactly what you wrote in Lesson 2 — and just change drawSprite() to draw a picture instead of shapes.

  • imageMode(CENTER) makes the image measure from its middle, matching how pos.x/pos.y work. Without it, your art sits down and to the right of your hitbox.
  • pushStyle() and popStyle() save and restore Processing's settings so imageMode does not leak out and affect everything else you draw.
  • The radius in super(...) is still your hitbox. The picture does not change that.
Same class, different drawing
class MyImageCharacter extends Blob {

  PImage img;                        // a variable that holds the picture

  MyImageCharacter(PApplet p, float x, float y, String fileName) {
    super(p, x, y, 30, color(0));    // the usual handshake line
    img = p.loadImage(fileName);     // load the picture once, at creation
  }

  void drawSprite() {
    parent.pushStyle();
    parent.imageMode(CENTER);                    // measure from the middle
    parent.image(img, pos.x, pos.y, 60, 60);     // draw at the sprite's position
    parent.popStyle();
  }
}

The two rules, side by side

  • Needs to collide (player, collectibles, hazards)? → extends Blob with a PImage inside.
  • Just needs to look nice (trees, background, clouds)? → ImageSprite.

Why your image has a white box around it

Because the PNG was saved without transparency. The image really is a rectangle — the background just happens to be white.

Fix it by finding or making a PNG that has a transparent background. Free tools like remove.bg will strip a background for you.

Build it step by step

  1. Find or draw a small PNG image for your character. A transparent background looks best. Free art: opengameart.org. Or draw a 32×32 character in any paint program.
  2. Open your sketch and choose Sketch → Show Sketch Folder.
  3. Make a new folder in there called data — exactly that, all lowercase.
  4. Drag your image file into data/. Note the file name exactly, including capitals and the extension.
  5. Start with the easy one. In your main sketch, add an ImageSprite decoration and draw it in draw(). Run it.
  6. If you get a blank or colored box: the file name does not match, the file is not in data/, or the PNG has no transparency.
  7. Adjust the size numbers until the proportions look right for your art.
  8. Now do your character. Make a new tab called MyImageCharacter and paste in the class below.
  9. In your main sketch, create a MyImageCharacter instead of a MyCharacter. Run it and move it around.
  10. Tune the radius in super(...) so the collisions feel fair — slightly smaller than the picture usually feels best.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab
// Bonus Lesson A - Images
// You need image files in your sketch's data/ folder.
// Sketch -> Show Sketch Folder, then drag PNG/JPG files into the data/ folder.

import coxprogramming.processing.sprites.*;

MyImageCharacter player;
ArrayList<ImageSprite> decorations;

void setup() {
  size(800, 600);

  // Player: your character using an image file (see MyImageCharacter tab)
  // Replace "hero.png" with your own file name.
  player = new MyImageCharacter(this, width/2, height/2, "hero.png");
  player.setVelocity(4, 0);

  // Decorations: ImageSprites placed around the scene
  // Replace "tree.png" with your own file name.
  decorations = new ArrayList<ImageSprite>();
  decorations.add(new ImageSprite(this, 150, 420, "tree.png", 60, 100));
  decorations.add(new ImageSprite(this, 400, 430, "tree.png", 60, 100));
  decorations.add(new ImageSprite(this, 650, 415, "tree.png", 60, 100));
}

void draw() {
  background(135, 206, 235);

  // Decorations drawn first (behind player)
  for (ImageSprite d : decorations) {
    d.drawSprite();
  }

  // Player drawn last (in front)
  player.followMouse();
  player.drawSprite();
}
New tab — MyImageCharacter.pde
// MyImageCharacter - like MyCharacter, but draws a picture instead of shapes.
// extends Blob means it still has collidesWith() for collision detection.
class MyImageCharacter extends Blob {

  PImage img;

  MyImageCharacter(PApplet p, float x, float y, String fileName) {
    super(p, x, y, 30, color(0));  // radius 30 - the invisible collision circle
    img = p.loadImage(fileName);
  }

  void drawSprite() {
    parent.pushStyle();
    parent.imageMode(CENTER);
    parent.image(img, pos.x, pos.y, 60, 60);  // drawn centered on the sprite's position
    parent.popStyle();
  }
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Find or draw your own character image. A PNG with a transparent background looks best by a mile.
  • Add a background image: ImageSprite bg = new ImageSprite(this, width/2, height/2, "background.png", width, height); drawn first in draw().
  • Adjust the display size (the 60, 60 in image()) so it matches your art's real proportions — a tall character squashed into a square looks wrong.
  • Give an ImageSprite decoration a velocity so it drifts across the scene.
  • Replace your collectibles with image sprites too — but remember they need extends Blob if the player has to collect them.

Finished early? Fake an animation: load two PImage fields and swap between them based on a frame counter. That is the whole idea behind Bonus Lesson C, and you will have discovered it yourself.
