Collisions!

Things finally touch each other — and that is when it becomes a game.

New idea: Detecting when two sprites overlap, and removing things from a list   |   Builds on: Lesson 6 — if, score, and gameOver.

What you will be able to do

  • Use collidesWith() to detect when your player touches another blob
  • Combine if with a collision to make something happen — collecting, scoring, losing
  • Remove items from an ArrayList safely with the backwards loop
  • Connect collisions to the score and game state you built last lesson

New words

collision — when two sprites overlap on screen
collidesWith(blob) — a method on Blob that gives back true when this sprite's circle overlaps another blob's circle
index — an item's position in a list. The first item is at index 0
hitbox — the invisible circle used to decide if something is touching. For your character it is the radius in the super(...) line

How it works

collidesWith() asks a yes-or-no question

The library checks whether two circles overlap and hands you back true or false. That is exactly the kind of thing an if wants.

  • This works because you wrote class MyCharacter extends Blob back in Lesson 2. Your character got collidesWith() for free, and you never had to write it.
The whole idea in one line
if (player.collidesWith(someCoin)) {
  // they're touching! do something
}

Your hitbox is the radius you set in Lesson 2

Remember the 30 in your super(...) line? That is the invisible circle the collision check uses. Your art does not matter to it — only that number does.

A bigger radius means collisions trigger from further away, which feels generous and forgiving. A smaller radius means you have to be right on top of something, which feels precise and harsh.

If your collisions feel wrong today, that number is what to change.

The problem with removing things while looping

When you collect a coin, you want it to disappear — you remove it from the list. But removing something from a list *while you are walking through that list* causes a real problem.

Picture five coins in a row. You are standing on coin 2 and you remove it. Every coin after it shifts back one place to fill the gap. Then the loop moves you forward to position 3… but the coin that *was* at 3 is now at 2, behind you. You just skipped it.

The fix: walk backwards

If you walk from the end toward the front, removing something only shifts items you have already passed. Nothing gets skipped.

You do not need to memorize why. Recognize it as "the safe way to remove things while looping" and copy it when you need it.

  • coins.size() is how many are in the list. - 1 because the last index is one less than the count.
  • i-- counts down instead of up.
  • coins.get(i) reaches into the list and hands you the item at that position.
The safe removal loop
for (int i = coins.size() - 1; i >= 0; i--) {
  Blob c = coins.get(i);      // grab the coin at position i
  c.move();
  c.drawSprite();

  if (player.collidesWith(c)) {
    coins.remove(i);          // take it out of the list
    score = score + 1;        // and score a point
  }
}

Winning when the list runs out

coins.size() shrinks every time you collect one. So the win condition writes itself:

An empty list means you got them all
if (coins.size() == 0) {
  gameOver = true;
}

Build it step by step

  1. Open your Lesson 6 sketch.
  2. Find the for-each loop inside playGame() that moves and draws your coins.
  3. Replace it with the backwards index loop from the starter code. Run it — nothing should look different yet.
  4. Inside that loop, add the if (player.collidesWith(c)) check with coins.remove(i); and score = score + 1; inside it.
  5. Run it and go collect a coin. It should vanish and your score should go up.
  6. If collisions feel too hard or too easy, open your MyCharacter tab and change the radius in the super(...) line.
  7. Change your win condition to if (coins.size() == 0) so you win by clearing the board.
  8. Now add hazards. Make a second ArrayList<Blob> of red blobs in setup(), using the same counting-loop pattern from Lesson 5.
  9. In playGame(), loop over the hazards with a for-each loop (you are not removing them, so no backwards loop needed) and set gameOver = true if the player touches one.
  10. Tune it until it is actually fun to play. How many hazards? How fast? That is a design decision and it is yours.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab (builds directly on Lesson 6)
// Lesson 7 - Collisions!
import coxprogramming.processing.sprites.*;

MyCharacter player;
ArrayList<Blob> coins;
int score = 0;
boolean gameOver = false;

void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);

  coins = new ArrayList<Blob>();
  for (int i = 0; i < 12; i++) {
    coins.add(new Blob(
      this, random(width), random(height),
      random(8, 18), random(-2, 2), random(-2, 2),
      color(255, 220, 50)
    ));
  }
}

void draw() {
  background(240);

  if (!gameOver) {
    playGame();
  } else {
    showGameOver();
  }
}

void playGame() {
  // Backwards loop - safe to remove coins while iterating
  for (int i = coins.size() - 1; i >= 0; i--) {
    Blob c = coins.get(i);
    c.move();
    c.drawSprite();

    if (player.collidesWith(c)) {
      coins.remove(i);   // collect the coin
      score = score + 1; // increase the score
    }
  }

  player.followMouse();
  player.drawSprite();

  // Win when all coins are collected
  if (coins.size() == 0) {
    gameOver = true;
  }

  fill(50);
  textSize(24);
  text("Score: " + score, 20, 36);
}

void showGameOver() {
  fill(80, 180, 80);
  textAlign(CENTER, CENTER);
  textSize(52);
  text("You Win!", width/2, height/2 - 20);
  textSize(22);
  text("Final score: " + score, width/2, height/2 + 26);
  textAlign(LEFT, TOP);
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Add a second ArrayList of obstacles (red blobs) that you have to dodge. Touching one costs a life or ends the game.
  • Spawn more coins when the player collects a certain number — add to the list right after removing from it.
  • Change what counts as winning. Clear the board? Reach a score? Survive for a while?
  • Make collected coins explode into two or three smaller blobs added to the list.
  • Tune your hitbox radius until the collisions feel fair.

Finished early? Make the game get harder as it goes: every time the player collects five coins, add two more hazards, or make the existing ones faster. Difficulty that responds to the player is what separates a demo from a game.
