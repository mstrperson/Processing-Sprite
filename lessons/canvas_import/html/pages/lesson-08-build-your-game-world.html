Build Your Game World

Stop making a sketch and start making a place.

New idea: Draw order and layering — and Block for terrain   |   Builds on: Lesson 7 — a working collect-and-avoid game.

What you will be able to do

  • Use Block to add ground, walls, sky, and other terrain
  • Explain that draw order decides layering — later draws go on top
  • Mix static sprites with moving ones to make a background feel alive
  • Design the world your game actually takes place in

New words

Block — a rectangle sprite from the library. Great for ground, walls, and platforms
draw order — the sequence you draw things in. Whatever is drawn later appears in front
static sprite — a sprite with no velocity. It sits in one place, but it is still a real sprite object
alpha — a fourth number in color() that sets transparency. 0 is invisible, 255 is solid

Before you code

💭 Think about it

On paper, sketch the world your game takes place in. What is in the background? Is there ground? Sky? Anything decorating it? Three minutes, then show a neighbor.

How it works

Block is a rectangle that stays put

Block is the library's rectangle sprite. Unlike Blob, it has no velocity — it is built to sit still and be scenery.

  • Watch out: for a Block, x and y are the top-left corner. For a Blob they were the center. This catches everyone once.
A strip of ground along the bottom
Block ground;

// in setup():
ground = new Block(this, 0, height - 80, width, 80, color(80, 160, 60));
//                       |      |          |      |        |
//                       |      |          |      |        +-- color
//                       |      |          |      +----------- height
//                       |      |          +------------------ width
//                       |      +----------------------------- y of the TOP-LEFT corner
//                       +------------------------------------ x of the TOP-LEFT corner

Draw order is the whole lesson

Processing draws like paint, not like a computer game engine. Whatever you draw later covers whatever you drew earlier. There is no depth, no 3D, no layers panel — just the order of your lines.

So the order of the calls in draw() *is* your layering.

  • Rule of thumb: background first, player last.
Back to front
void draw() {
  background(135, 206, 235);   // 1. sky - furthest back

  for (Blob d : decorations) { // 2. clouds drifting behind everything
    d.move();
    d.drawSprite();
  }

  ground.drawSprite();         // 3. ground on top of the sky

  // ... coins ...              // 4. things in the world

  player.drawSprite();         // 5. player - always last, always in front
}

background() wipes the slate every frame

Remember from Lesson 1 that background() erases everything. That is why it goes at the top of draw().

Everything after it is layered onto a clean canvas, in the order you wrote it. If you call background() halfway through draw(), you erase everything you already drew that frame.

Transparency makes things look far away

color() takes an optional fourth number: transparency, called alpha. 0 is completely invisible, 255 is completely solid.

Semi-transparent decorations look soft and distant, which is a cheap and very effective way to create depth.

A faint cloud
color(255, 255, 255, 180)   // white, slightly see-through

Static and moving sprites together

A world feels alive when some of it moves and most of it does not. Ground sits still. Clouds drift slowly. Coins bounce around. The player darts.

Different speeds at different layers is what makes a scene read as a *place* rather than a pile of shapes.

Build it step by step

  1. Open your Lesson 7 sketch. All your game logic stays — you are adding a world around it.
  2. Declare Block ground; at the top of your sketch.
  3. In setup(), create it: ground = new Block(this, 0, height - 70, width, 70, color(80, 160, 60));
  4. In draw(), after background(), add ground.drawSprite();. Run it. You should have a strip of green along the bottom.
  5. Change background(240) to a color that fits your world — sky blue, deep space black, ocean teal, lava red.
  6. Experiment with draw order: move ground.drawSprite() to the very last line of draw() and run. Your player is now buried under the ground. Move it back and say out loud what happened.
  7. Add background decorations: an ArrayList<Blob> created with a counting loop in setup(), drawn first in draw(). Give them a slow drift and use a fourth alpha number in their color.
  8. Add a second Block — a wall, a platform, a ceiling. Put it somewhere that changes how the game feels to play.
  9. Restyle your coins and hazards so they belong in this world. Gold coins in a space game look wrong. Make them asteroids, or stars, or fish.
  10. Play it. Does it look like a place? Keep going until it does.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab
// Lesson 8 - Build Your Game World
import coxprogramming.processing.sprites.*;

MyCharacter player;
ArrayList<Blob> coins;
Block ground;
ArrayList<Blob> decorations;  // clouds, stars, trees - whatever fits your theme
int score = 0;
boolean gameOver = false;

void setup() {
  size(800, 600);

  // Ground strip along the bottom
  ground = new Block(this, 0, height - 70, width, 70, color(80, 160, 60));

  // Background decorations (slow-moving clouds, drifting stars, etc.)
  decorations = new ArrayList<Blob>();
  for (int i = 0; i < 5; i++) {
    decorations.add(new Blob(
      this, random(width), random(height * 0.7),
      random(20, 50), random(0.2, 0.8), 0,
      color(255, 255, 255, 180)  // semi-transparent white blobs as clouds
    ));
  }

  // Player
  player = new MyCharacter(this, width/2, height - 120);
  player.setVelocity(4, 0);

  // Coins
  coins = new ArrayList<Blob>();
  for (int i = 0; i < 10; i++) {
    coins.add(new Blob(
      this, random(width), random(100, height - 100),
      random(8, 16), random(-2, 2), random(-1, 1),
      color(255, 220, 50)
    ));
  }
}

void draw() {
  background(135, 206, 235);  // sky blue - change to match your theme

  // 1. Background decorations (drawn first = appear behind everything)
  for (Blob d : decorations) {
    d.move();
    d.drawSprite();
  }

  // 2. Ground (drawn after sky, before player)
  ground.drawSprite();

  if (!gameOver) {
    playGame();
  } else {
    showGameOver();
  }
}

void playGame() {
  for (int i = coins.size() - 1; i >= 0; i--) {
    Blob c = coins.get(i);
    c.move();
    c.drawSprite();
    if (player.collidesWith(c)) {
      coins.remove(i);
      score = score + 1;
    }
  }

  // 3. Player (drawn last = appears in front of everything)
  player.followMouse();
  player.drawSprite();

  if (coins.size() == 0) {
    gameOver = true;
  }

  fill(50);
  textSize(24);
  text("Score: " + score, 20, 36);
}

void showGameOver() {
  fill(80, 180, 80);
  textAlign(CENTER, CENTER);
  textSize(52);
  text("You Win!", width/2, height/2);
  textAlign(LEFT, TOP);
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Replace the sky-blue background with your theme. Space? Underwater? Lava? A cave? A candy world?
  • Write a new decoration sprite class in a tab — a Tree, a Star, a Fish, a Rock. Same extends Blob pattern as Lesson 2.
  • Add multiple Blocks to make platforms, walls, or a border that shapes how the game plays.
  • Change your coins and hazards to match the theme — gems, fish, stars, hearts, asteroids.
  • Use transparency (color(r, g, b, alpha)) on your background layer so it recedes.
  • Give background decorations a much slower speed than foreground objects. That difference alone reads as depth.

Finished early? Build a real parallax effect: three layers of decorations at three different speeds — slow and faint at the back, faster and solid at the front. It is the oldest trick in 2D games and it still works.
