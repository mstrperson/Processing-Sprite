Bring It to Life

Your character stops sitting there and starts moving on its own.

New idea: Velocity — changing position over time   |   Builds on: Lesson 2 — your MyCharacter class. Keep that tab exactly as it is.

What you will be able to do

  • Use setVelocity(vx, vy) to give your character a speed and a direction
  • Call move() every frame to animate it
  • Explain what screen wrapping is and when it happens
  • Use random() to make things different every time you run

New words

velocity — how fast something moves and which way. It has two parts: left/right (vx) and up/down (vy)
frame — one single picture in the animation. draw() produces one frame per tick, about 60 every second
random(a, b) — picks a surprise number between a and b, fresh every time it is called
wrap — when a sprite goes off one edge of the screen and reappears on the opposite edge

Before you code

💭 Think about it

Where does your character get drawn on the screen? Which function draws it, and how many times per second does that happen?

How it works

Velocity is two numbers, not one

"Speed" in a game is really two separate questions: how fast am I going sideways, and how fast am I going up or down? So velocity is two numbers.

  • vx is left and right. Positive goes right →. Negative goes left ←.
  • vy is up and down. Positive goes DOWN ↓. Negative goes UP ↑.

Yes, positive y really is down

This trips up almost everyone. On a math graph, y goes up. On a screen, y goes down — y = 0 is the top edge, and bigger y means further down.

So setVelocity(3, -2) means: 3 pixels right and 2 pixels up, every frame.

Velocity alone does nothing

Setting a velocity is like telling someone how fast to walk. Until they actually take a step, nothing happens.

move() is the step. It takes the velocity and adds it to the position, once. So it has to be inside draw(), where it happens 60 times a second.

The order that matters
void draw() {
  background(240);
  player.move();        // 1. update the position
  player.drawSprite();  // 2. THEN draw at the new position
}

Move first, then draw

If you draw before you move, you are drawing your character where it *used to be*. It is off by one frame, forever. It is a small bug and mostly harmless, but it is a good habit to get right: move, then draw.

Wrapping is free

Run it and wait. When your character slides off the right edge, it comes back in on the left. Off the top, back in at the bottom.

You did not write that. The library does it for you inside move(). That is the "magic toolbox" idea — you push the button, the button works.

random() makes every run different

random(-5, 5) picks a new number between -5 and 5 each time it runs. Put it where a velocity number goes and your character takes off in a different direction every single time you press Run.

A different character every run
player.setVelocity(random(-5, 5), random(-5, 5));

Build it step by step

  1. Open your Lesson 2 sketch. Keep the MyCharacter tab exactly as it is — you are only changing the main tab.
  2. In setup(), after you create the player, add: player.setVelocity(3, -2);
  3. Press ▶ Run. Nothing moves. That is expected — you told it a speed but never told it to take a step.
  4. In draw(), add player.move(); on the line before player.drawSprite();
  5. Run again. Your character should drift up and to the right. Watch what happens when it reaches an edge.
  6. Change the velocity to (8, 0). Run. Now (0.5, 0). Run. Fast and slow.
  7. Try exact diagonal: (3, 3). Then try (3, -3). Which way does each one go?
  8. Replace both numbers with random(-5, 5) and press Run five times in a row. Different every time.
  9. Change the background color to set a mood for your character's world.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab (MyCharacter.pde is unchanged from Lesson 2)
// Lesson 3 - Bring It to Life
import coxprogramming.processing.sprites.*;

MyCharacter player;

void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(3, -2);  // 3 pixels right, 2 pixels up per frame
}

void draw() {
  background(240);
  player.move();        // update position (do this BEFORE drawing)
  player.drawSprite();  // draw at new position
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Try random(-5, 5) for both velocity values in setup(), then run it several times.
  • Make your character move really fast. Then really slow. Which one suits it?
  • Make it move exactly diagonally — that means vx and vy have the same size.
  • Change the background color to set a mood. A drifting character on dark blue reads completely differently than on white.
  • Add a second blob with its own velocity so there is something else alive on screen.

Finished early? Comment out background(240) and run. Your character leaves a trail, because nothing is erasing the old frames. Some of the best-looking sketches do this on purpose.
