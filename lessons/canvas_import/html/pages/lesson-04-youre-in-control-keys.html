New words

input -- information coming into the program from you -- the mouse, the keyboard
event function -- a function Processing calls automatically when something happens once, like a click or a key press
mousePressed() -- runs once, each time you click the mouse
keyPressed() -- runs when a key is pressed; holding a key may trigger repeated calls
continuous input -- something checked every single frame, inside draw() -- like "where is the mouse right now?"

How it works

Today the class splits in two

Half the class is learning to steer with the arrow keys.  That's you.  The other half is learning the mouse.

In about fifteen minutes you meet up at your table and teach each other.  So as you work, notice what surprises you.  That's what you'll share.

Two very different kinds of input

A key press is an event.  It happens once, at one instant, so Processing comes and tells the program by calling keyPressed().  Holding a key may generate repeated key-press events.

The Mouse Group uses the other kind, continuous input:  "where is the mouse right now?" has an answer every frame, so it gets asked in draw().  You'll see it at your table.

keyboardControl()

keyboardControl() reads the arrow keys and sets your character's velocity to match.  It goes inside keyPressed(), not draw().

So a key press changes the velocity, once.  Then move() in draw() uses that velocity, every frame.

  • Click inside the sketch window first.  Until you do, the keys go to the code editor.
  • Keep move() in draw().  Without it, every key press sets a velocity and nothing ever takes the step.
Arrow-key control
void draw() {
  background(240);
  player.move();        // still needed - applies the velocity each frame
  player.drawSprite();
}

void keyPressed() {
  player.keyboardControl();   // arrow keys change the velocity
}

Your character coasts, and that is not a bug

Press an arrow key and let go.  Your character keeps going.

That is correct.  keyboardControl() sets the velocity, and letting go of the key leaves it just as it was.  It feels like ice skating.  Some games want exactly that.

An arrow sets a speed of 5 in that direction.  Any other key sets the velocity to zero, so every key that isn't an arrow is a brake.

Build it step by step

  1. Open your Lesson 3 sketch.  The MyCharacter tab still does not change.
  2. Make sure player.setVelocity(4, 0); is in setup(), and player.move(); is still in draw().
  3. At the very bottom of your sketch, after the closing brace of draw(), add a keyPressed() function with player.keyboardControl(); inside it.
  4. Press ▶ Run, and wait a second before you touch anything.  Your character drifts slowly right.  That's the setVelocity(4, 0), and move() using it, the same as Lesson 3.
  5. Click inside the sketch window, then use the arrow keys.  Each arrow sends your character that way.
  6. Press an arrow and let go.  Notice it keeps going.  That is the coasting.
  7. Press the space bar.  Then try a letter key.  What do they do?
  8. Change the numbers in setVelocity() and run again.  What changes?  (Look before and after your first key press.)
  9. Write down one thing that surprised you, to tell your table.

Starter code

This code runs exactly as it is.  Get it running first, then start changing it.

Main sketch tab
// Lesson 4 - You're in Control (Keys Group)
import coxprogramming.processing.sprites.*;

MyCharacter player;

void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);  // the drift before your first key
}

void draw() {
  background(240);
  player.move();        // still needed - applies the velocity each frame
  player.drawSprite();
}

// Arrow keys change the velocity
void keyPressed() {
  player.keyboardControl();
}

Make it yours

⭐ This is the part that matters most.  Pick at least one and make it yours.

  • Decide how you feel about the coasting.  Ice skating, or a problem?  (The challenge below fixes it.)
  • Add a mousePressed() that does something fun -- try player.moveTo(mouseX, mouseY); to teleport.
  • Combine them:  arrow keys to drive, plus a click ability.
  • Add a second, non-player blob that moves on its own (copy the pattern from Lesson 3) so the screen is not empty.

Finished early?  Make the character stop when you release the key.  Add a keyReleased() function with player.setVelocity(0, 0); inside it.  Now compare the two feels -- which one suits your character?
