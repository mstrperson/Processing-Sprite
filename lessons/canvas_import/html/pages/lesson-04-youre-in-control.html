You're in Control

Your character stops doing its own thing and starts doing what you tell it.

New idea: Input — the program reacting to you   |   Builds on: Lesson 3 — setVelocity() and move().

What you will be able to do

  • Use followMouse() to make your character chase the cursor
  • Use keyboardControl() to drive your character with the arrow keys
  • Explain the difference between continuous input and an event
  • Use mousePressed() to make something happen once per click

New words

input — information coming into the program from you — the mouse, the keyboard
event function — a function Processing calls automatically when something happens once, like a click or a key press
mousePressed() — runs once, each time you click the mouse
keyPressed() — runs once, each time you press a key down
continuous input — something checked every single frame, inside draw() — like "where is the mouse right now?"

Before you code

💭 Think about it

What does move() do, and where does it go? What happens if you leave it out?

How it works

Two very different kinds of input

This is the real idea of the lesson, and it is worth slowing down for.

Some questions have an answer all the time: "where is the mouse right now?" You can ask that on every frame. That is continuous input, and it belongs in draw().

Other things happen at a single moment: "the player just pressed the left arrow." There is no answer 59 frames out of 60 — there is just the instant it happened. That is an event, and it belongs in an event function like keyPressed().

Option A: followMouse()

followMouse() pulls your character toward the cursor a little bit, every frame. So it goes inside draw().

  • You must set a velocity first. followMouse() uses the size of your velocity as its chase speed. If the velocity is zero, your character will not move an inch and it will look broken.
  • When you use followMouse(), do not also call move(). followMouse() moves the position itself. Calling both fights over the same character.
Following the mouse
void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);   // REQUIRED - this is the speed it chases at
}

void draw() {
  background(240);
  player.followMouse();
  player.drawSprite();
}

Option B: keyboardControl()

keyboardControl() reads the arrow keys and sets your character's velocity to match. It goes inside keyPressed(), not draw().

Why? Because draw() runs 60 times a second whether or not you touched a key. keyPressed() only fires at the exact moment a key goes down — which is the only moment there is anything to read.

Arrow-key control
void draw() {
  background(240);
  player.move();        // still needed - applies the velocity each frame
  player.drawSprite();
}

void keyPressed() {
  player.keyboardControl();   // arrow keys change the velocity
}

Your character coasts, and that is not a bug

Press an arrow key and let go. Your character keeps going.

That is correct. keyboardControl() sets the velocity, and nothing ever un-sets it. Releasing the key does not tell the character to stop — nobody asked it to.

It feels like ice skating. Some games want exactly that. If yours does not, that is a great thing to fix later.

mousePressed() — once per click

mousePressed() is another event function. Whatever you put inside it happens exactly once, each time you click.

Snap to the mouse on click
void mousePressed() {
  player.moveTo(mouseX, mouseY);   // teleport to wherever you clicked
}

Build it step by step

  1. Open your Lesson 3 sketch. The MyCharacter tab still does not change.
  2. Try Option A first. In draw(), replace player.move(); with player.followMouse();
  3. Make sure player.setVelocity(4, 0); is still in setup(). Without it, nothing will move.
  4. Press ▶ Run and move your mouse around. Your character should chase the cursor.
  5. Change the 4 in setVelocity to 1, then to 12. Slow and stalky, or fast and twitchy?
  6. Now try Option B. Comment out the followMouse() line and put player.move(); back.
  7. Add a keyPressed() function at the bottom of your sketch with player.keyboardControl(); inside it.
  8. Run it. Click inside the sketch window first — the keyboard is ignored until the window has focus. Now use the arrow keys.
  9. Press an arrow and let go. Notice it keeps going. That is the coasting.
  10. Pick the control style you want to use for the rest of the unit, and delete or comment out the other one.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab
// Lesson 4 - You're in Control
import coxprogramming.processing.sprites.*;

MyCharacter player;

void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);  // sets the speed used by followMouse()
}

void draw() {
  background(240);

  // --- Option A: follow the mouse ---
  player.followMouse();
  player.drawSprite();

  // --- Option B: arrow-key control ---
  // (comment out Option A and uncomment these two lines)
  // player.move();
  // player.drawSprite();
}

// Arrow keys control the character (used with Option B)
void keyPressed() {
  player.keyboardControl();
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Try both control modes, then pick the one you want for the rest of the unit.
  • If you chose followMouse(): tune the speed in setVelocity() until the chase feels right.
  • Add a second, non-player blob that moves on its own (copy the pattern from Lesson 3) so the screen is not empty.
  • If you chose keyboardControl(): add a mousePressed() that does something fun — try player.moveTo(mouseX, mouseY); to teleport.
  • Combine them: arrow keys to drive, plus a click ability.

Finished early? Make the character stop when you release the key. Add a keyReleased() function with player.setVelocity(0, 0); inside it. Now compare the two feels — which one suits your character?
