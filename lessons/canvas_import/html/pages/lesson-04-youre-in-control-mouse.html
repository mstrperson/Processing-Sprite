New words

input -- information coming into the program from you -- the mouse, the keyboard
event function -- a function Processing calls automatically when something happens once, like a click or a key press
mousePressed() -- runs once, each time you click the mouse
keyPressed() -- runs when a key is pressed; holding a key may trigger repeated calls
continuous input -- something checked every single frame, inside draw() -- like "where is the mouse right now?"

How it works

Today the class splits in two

Half the class is learning to steer with the mouse.  That's you.  The other half is learning the arrow keys.

In about fifteen minutes you meet up at your table and teach each other.  So as you work, notice what surprises you.  That's what you'll share.

Two very different kinds of input

Some questions have an answer all the time:  "where is the mouse right now?"  You can ask that on every frame.  That is continuous input, and it belongs in draw().

Your group uses that kind.  The Keys Group uses the other kind, an event:  a key press happens once, and Processing comes and tells the program.  You'll see it at your table.

followMouse()

followMouse() pulls your character toward the cursor a little bit, every frame.  So it goes inside draw().

  • You must set a velocity first.  followMouse() uses the size of your velocity as its chase speed.  If the velocity is zero, your character will not move an inch and it will look broken.
  • Use followMouse() or move(), one or the other.  followMouse() moves the position itself.
Following the mouse
void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);   // REQUIRED - this is the speed it chases at
}

void draw() {
  background(240);
  player.followMouse();
  player.drawSprite();
}

mousePressed() - once per click

mousePressed() is an event function, the same kind the Keys Group is using.  Whatever you put inside it happens exactly once, each time you click.

Snap to the mouse on click
void mousePressed() {
  player.moveTo(mouseX, mouseY);   // teleport to wherever you clicked
}

Build it step by step

  1. Open your Lesson 3 sketch.  The MyCharacter tab still does not change.
  2. Make sure player.setVelocity(4, 0); is in setup().  Without it, nothing will move.
  3. In draw(), replace player.move(); with player.followMouse();
  4. Press ▶ Run and move your mouse around.  Your character should chase the cursor.  Hold the mouse still, and watch it slide straight there.
  5. Change the 4 in setVelocity to 1, then to 12.  Slow and stalky, or fast and twitchy?
  6. Try setVelocity(0, 5), and then setVelocity(5, 0).  Is one faster?  followMouse() only cares how big the velocity is, and ignores which way it points.
  7. Put player.move(); back in draw(), right under followMouse(), and run it.  Your character never quite reaches the mouse.  It parks next to it, on the side its velocity points.  Take move() back out.
  8. Write down one thing that surprised you, to tell your table.

Make it yours

⭐ This is the part that matters most.  Pick at least one and make it yours.

  • Tune the speed in setVelocity() until the chase feels right for your character.
  • Add a mousePressed() that does something fun -- try player.moveTo(mouseX, mouseY); to teleport.
  • Add a second, non-player blob that moves on its own (copy the pattern from Lesson 3) so the screen is not empty.

Finished early?  Make a click speed your character up.  Put player.setVelocity(12, 0); inside mousePressed().  Then add a keyPressed() with player.setVelocity(4, 0); inside it, so any key slows it back down.  That's two event functions, both changing the chase speed.
