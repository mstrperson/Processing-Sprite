If This, Then That

Your program starts making decisions instead of just following orders.

New idea: if statements and variables that change   |   Builds on: Lesson 5 — your world full of objects.

What you will be able to do

  • Use an if statement to make your program choose what to do
  • Declare variables that track information over time, like int score
  • Show text and numbers on screen with text()
  • Explain that a program can be in different states — playing, game over

New words

if statement — "if this is true, do this block of code"
boolean — a value that is only ever true or false. Nothing in between
variable — a named container for a value. int score = 0; names a box called score that starts at zero
int — a variable that holds a whole number — 0, 7, -3. No decimals
text() — a Processing function that draws words or numbers on the screen
state — which mode your program is in right now — playing, or game over, or paused

How it works

Variables that live at the top

Up until now your variables have been things you created and used. Now you need variables that remember something across frames — like a score that keeps going up.

Those go at the very top of your sketch, outside setup() and outside draw().

  • Written up there, every function can see them.
  • Written inside setup(), they vanish the second setup() finishes and draw() cannot see them at all.
Global variables
MyCharacter player;
ArrayList<Blob> coins;
int score = 0;              // a whole number, starts at zero
boolean gameOver = false;   // true or false, starts false

void setup() { ... }

The if statement

An if asks a yes-or-no question. If the answer is yes, the code inside the braces runs. If not, it is skipped entirely.

  • The thing in the parentheses is a condition — it is either true or false.
  • > greater than, < less than, >= at least, <= at most, == exactly equal.
  • Careful: == is a question ("are these equal?"). A single = is a command ("make this equal to that"). Mixing them up is a classic.
A question and an answer
if (score > 10) {
  background(255, 0, 0);   // only happens when score is over 10
}

booleans and the ! operator

A boolean is the simplest possible variable: it is true or it is false.

! means NOT. So !gameOver reads as "not game over" — in other words, "the game is still going."

Two states, one choice
if (!gameOver) {
  playGame();       // still playing
} else {
  showGameOver();   // it's over
}

Putting text on screen

text() draws words. You give it what to say and where to put it.

  • The + glues the words "Score: " and the number score together into one piece of text.
  • Set fill() before text(), or your text takes whatever color the last shape used.
Showing the score
fill(50);                          // the text color
textSize(24);                      // how big
text("Score: " + score, 20, 36);   // what, then x, then y

States: your program has modes

This is the big idea. Your game is not one thing — it is in a mode. Right now there are two: playing, and game over.

The boolean gameOver remembers which mode you are in, and the if/else in draw() picks which one to run. Everything else follows from that.

Build it step by step

  1. Open your Lesson 5 sketch.
  2. At the very top, above setup(), add: int score = 0; and boolean gameOver = false;
  3. In draw(), after background(), add a text() call showing the score. Run it. You should see Score: 0 in the corner.
  4. Test it: temporarily change int score = 0; to int score = 7; and run. The display should change. Set it back to 0.
  5. Now move all your game code out of draw() and into a new function called playGame(). Look at the starter code to see exactly how.
  6. In draw(), add the if (!gameOver) { playGame(); } else { showGameOver(); } block.
  7. Write the showGameOver() function. Run it — it should still play normally, since gameOver is false.
  8. Test the other branch: temporarily change boolean gameOver = false; to true and run. You should jump straight to the game over screen. Set it back.
  9. Add the trigger: inside playGame(), if (score >= 10) { gameOver = true; }
  10. Change what triggers game over, and restyle the game over screen so it sounds like your game.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab
// Lesson 6 - If This, Then That
import coxprogramming.processing.sprites.*;

MyCharacter player;
ArrayList<Blob> coins;
int score = 0;
boolean gameOver = false;

void setup() {
  size(800, 600);
  player = new MyCharacter(this, width/2, height/2);
  player.setVelocity(4, 0);

  coins = new ArrayList<Blob>();
  for (int i = 0; i < 10; i++) {
    coins.add(new Blob(
      this, random(width), random(height),
      random(8, 18), random(-2, 2), random(-2, 2),
      color(255, 220, 50)
    ));
  }
}

void draw() {
  background(240);

  if (!gameOver) {
    playGame();
  } else {
    showGameOver();
  }
}

void playGame() {
  for (Blob c : coins) {
    c.move();
    c.drawSprite();
  }

  player.followMouse();
  player.drawSprite();

  // When score reaches 10, trigger game over
  if (score >= 10) {
    gameOver = true;
  }

  // Display the score
  fill(50);
  textSize(24);
  text("Score: " + score, 20, 36);
}

void showGameOver() {
  fill(80, 180, 80);
  textAlign(CENTER, CENTER);
  textSize(52);
  text("You Win!", width/2, height/2 - 20);
  textSize(22);
  text("Final score: " + score, width/2, height/2 + 26);
  textAlign(LEFT, TOP);  // reset alignment so score display still works
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Change what triggers game over. A time limit? A score above 20? Something else entirely?
  • Restyle the game over screen — different words, different colors, a message that fits your game.
  • Add a second variable: a lives counter that starts at 3 and counts down.
  • Make the background color change as the score goes up — a few if statements stacked up.
  • Show more than the score. A timer, a level number, a message that appears at a milestone.

Finished early? Make the game react in layers — the background shifts at score 5, the text turns red at score 8, and lives count down at the same time. Multiple variables and multiple conditions working together.
