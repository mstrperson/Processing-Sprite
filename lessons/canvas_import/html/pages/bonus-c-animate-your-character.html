Animate Your Character

Stop sliding a frozen drawing around. Make it move.

When to use this: Any time after Lesson 2 (you need a character to animate). It shines most during Lesson 9, when students want their character to feel alive. Pairs naturally with Bonus Lesson A — image frames animate the same way. One period.

New idea: A flipbook of poses — AnimatedSprite   |   Builds on: Lesson 2 — your MyCharacter drawing. You will reuse it directly.

What you will be able to do

  • Understand animation as a flipbook: several still pictures shown fast, one after another
  • Draw your character in two to four slightly different poses
  • Use AnimatedSprite to hold those poses and flip between them automatically
  • Control the speed with setFrameRate()

New words

animation frame — one still picture in the flipbook — one pose of your character
pose — one version of your character's drawing. Mouth open vs. closed, legs together vs. apart
AnimatedSprite — a library object that holds several frame sprites and draws one at a time
frame rate (animation) — how many game frames each picture stays on screen. 8 means "hold each pose for 8 game frames." Smaller is faster

Before you code

💭 Think about it

Have you ever made a flipbook in the corner of a notebook? How does a cartoon make a character walk? It is just drawings, shown fast. And remember from Lesson 1 — draw() is already a flipbook, drawing a new picture about 60 times a second.

How it works

Two different things are both called a frame

This is worth getting straight before anything else, because the word does double duty.

A game frame is one run of draw() — about 60 of them every second. You have known this since Lesson 1.

An animation frame is one picture in your flipbook — one pose of your character.

setFrameRate(8) is what connects them: hold each animation frame for 8 game frames.

A frame is just a drawing you already know how to make

A frame class is your Lesson 2 character with one addition: a pose number. The same class draws several slightly different versions depending on that number.

  • Only change what should move. Keep everything else identical between poses, or it looks like flickering instead of animation.
One class, several poses
class MyCharacterFrame extends Blob {

  int pose;   // which version to draw: 0, 1, 2, ...

  MyCharacterFrame(PApplet p, float x, float y, int pose) {
    super(p, x, y, 30, color(100, 180, 255));   // the same handshake line
    this.pose = pose;
  }

  void drawSprite() {
    // ... body and eyes: IDENTICAL in every pose ...

    if (pose == 0) {
      arc(pos.x, pos.y + 6, 24, 18, 0, PI);   // open smile
    } else if (pose == 1) {
      arc(pos.x, pos.y + 6, 24, 8, 0, PI);    // smaller smile
    } else {
      ellipse(pos.x, pos.y + 10, 12, 12);     // round talking mouth
    }
  }
}

Building the flipbook

This is the one genuinely new line in the lesson. You chain the calls together to build up the flipbook.

  • FromSprite(...) starts the flipbook with the first page.
  • AddFrameSprite(...) adds another page. Add as many as you like.
  • setFrameRate(8) sets how long each page stays up.
  • Create every frame at the SAME x and y. If you do not, your character visibly jumps every time the page turns.
Three poses into one animated sprite
player = AnimatedSprite.FromSprite(new MyCharacterFrame(this, width/2, height/2, 0))
    .AddFrameSprite(new MyCharacterFrame(this, width/2, height/2, 1))
    .AddFrameSprite(new MyCharacterFrame(this, width/2, height/2, 2))
    .setFrameRate(8);

Frame rate is backwards from what you would guess

setFrameRate() is game frames per picture — how long to hold each pose. So a smaller number means a faster animation.

setFrameRate(4) is fast and frantic. setFrameRate(20) is slow and calm. The smallest allowed is 1, and the default is 8 if you never call it.

Everything else works exactly as before

An AnimatedSprite is still a sprite. move(), followMouse(), keyboardControl() — all the same as Lessons 3 and 4.

drawSprite() draws the current pose and turns the page for you. You do not have to manage any of it.

One honest catch, if you are using this in Lesson 9

An AnimatedSprite is not a Blob, so collidesWith() is not available on it. That is the trade for getting animation.

Use distanceTo() instead. It works between any two sprites:

  • Pick a number that matches your character's size. Bigger is more forgiving, exactly like the radius was.
Collision without collidesWith
if (player.distanceTo(coin) < 40) {   // 40 = how close counts as "touching"
  collectibles.remove(i);
  score = score + 1;
}

Build it step by step

  1. Make a new tab called MyCharacterFrame.
  2. Copy your whole character drawing from your Lesson 2 MyCharacter tab into it, then rename the class and constructor to MyCharacterFrame.
  3. Add the int pose; field and the this.pose = pose; line in the constructor, matching the starter code below.
  4. Pick one thing on your character to animate — the mouth is easiest. Legs, arms, wings, or ears also work well.
  5. Wrap just that part in an if (pose == 0) { ... } else if (pose == 1) { ... }. Make the difference small.
  6. In your main sketch, build the AnimatedSprite from two frames. Both at the same x and y.
  7. Run it. Your character should be flipping between two poses on its own.
  8. Add a third pose. Then try setFrameRate(4) and setFrameRate(20) and see which speed suits your character.
  9. Move it: add player.followMouse() or arrow-key control, exactly like Lesson 4. Animation and motion work together with no extra effort.
  10. If your character jumps or twitches when the pose changes, two things to check: are all frames at the same x and y, and are the non-moving parts truly identical between poses?

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

New tab — MyCharacterFrame.pde
// MyCharacterFrame - ONE POSE of your character.
// It's just like your MyCharacter from Lesson 2, but the "pose" number lets you
// draw a few slightly different versions. AnimatedSprite flips between them.
class MyCharacterFrame extends Blob {

  int pose;  // which version to draw: 0, 1, 2, ...

  MyCharacterFrame(PApplet p, float x, float y, int pose) {
    super(p, x, y, 30, color(100, 180, 255));  // same handshake line as MyCharacter
    this.pose = pose;
  }

  void drawSprite() {
    // --- Body (same in every pose) ---
    fill(100, 180, 255);
    noStroke();
    ellipse(pos.x, pos.y, 60, 60);

    // --- Eyes (same in every pose) ---
    fill(255);
    ellipse(pos.x - 12, pos.y - 8, 16, 16);
    ellipse(pos.x + 12, pos.y - 8, 16, 16);
    fill(30);
    ellipse(pos.x - 12, pos.y - 8, 8, 8);
    ellipse(pos.x + 12, pos.y - 8, 8, 8);

    // --- Mouth: CHANGES with the pose - this is what makes it animate! ---
    stroke(30);
    strokeWeight(2);
    noFill();
    if (pose == 0) {
      arc(pos.x, pos.y + 6, 24, 18, 0, PI);   // open smile
    } else if (pose == 1) {
      arc(pos.x, pos.y + 6, 24, 8, 0, PI);    // smaller smile
    } else {
      fill(30);
      ellipse(pos.x, pos.y + 10, 12, 12);     // round "talking" mouth
    }
  }
}
Main sketch tab
// Bonus Lesson C - Animate Your Character
import coxprogramming.processing.sprites.*;

AnimatedSprite player;

void setup() {
  size(800, 600);

  // Build the flipbook from several poses - all at the SAME spot so it doesn't jump.
  // AnimatedSprite shows one pose at a time and flips between them for you.
  player = AnimatedSprite.FromSprite(new MyCharacterFrame(this, width/2, height/2, 0))
      .AddFrameSprite(new MyCharacterFrame(this, width/2, height/2, 1))
      .AddFrameSprite(new MyCharacterFrame(this, width/2, height/2, 2))
      .setFrameRate(8);   // hold each pose for 8 game frames; smaller = faster

  player.setVelocity(4, 0);  // gives followMouse() a speed to move at
}

void draw() {
  background(240);

  // --- Option A: follow the mouse ---
  player.followMouse();
  player.drawSprite();   // draws the current pose, then turns the page for you

  // --- Option B: arrow-key control ---
  // (comment out Option A above, uncomment these two lines, keep keyPressed below)
  // player.move();
  // player.drawSprite();
}

// Used with Option B (arrow keys)
void keyPressed() {
  player.keyboardControl();
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Add a fourth pose. Try animating legs or arms instead of the mouth — make it walk.
  • Change setFrameRate(). Try 4 (fast and frantic) and 20 (slow and calm). Which one is your character?
  • Add more frames for smoother motion. More pages means a smoother flipbook.
  • Make a second animated creature — a pet? — with its own setVelocity() drifting across the scene.
  • Plug it into your Lesson 9 game. Remember: use distanceTo() instead of collidesWith(), because an AnimatedSprite is not a Blob.

Finished early? Take manual control of the flipbook. Instead of letting it auto-advance, call nextFrame() or setFrameNumber(n) on a key press to trigger a specific pose — a jump, an attack, a blink. That is how real games do special moves.
