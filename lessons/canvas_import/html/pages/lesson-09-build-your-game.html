The one new idea: restartGame()

To restart a game, you might think you need to undo everything that happened. You do not. That is much harder and it never quite works.

Instead, you just run the setup steps again: make a new player, empty the lists and refill them, set the score back to 0, and set the flags back to false.

  • Notice that setup() now just calls restartGame(). Starting the game and restarting it are the same thing, so they should be the same code.
  • That is a genuinely important programming idea, and it is worth noticing that it made your code shorter, not longer.
Reset by rebuilding
void restartGame() {
  score = 0;
  gameOver = false;
  playerWon = false;

  player = new MyCharacter(this, width/2, height - 120);
  player.setVelocity(4, 0);

  collectibles = new ArrayList<Blob>();   // a brand-new empty list
  for (int i = 0; i < 10; i++) {
    collectibles.add(new Blob(...));
  }
}

Three states now, not two

Lesson 6 had two states: playing and game over. A real game usually has three — because winning and losing should not look the same.

  • && means AND. So !gameOver && !playerWon reads: "not lost, and not won" — in other words, still playing.
Picking which screen to show
if (!gameOver && !playerWon) {
  playGame();
} else if (playerWon) {
  showWin();
} else {
  showGameOver();
}

Clicking to play again

mousePressed() from Lesson 4 is an event function. Put the restart inside it, but guard it with an if so a click during play does not wipe your game.

  • || means OR. "If we lost or we won, start over."
Only restart when it is over
void mousePressed() {
  if (gameOver || playerWon) {
    restartGame();
  }
}

Build it step by step

  1. Write your one-sentence game description first. What is it about? Do this before touching code.
  2. Start from your Lesson 8 sketch, or paste in the starter below — whichever is closer to what you want.
  3. Run it and find each piece: setup, draw, playGame, showWin, showGameOver, restartGame, mousePressed. Say out loud what each one does.
  4. Play it until you lose, then click to restart. Make sure that works before you change anything.
  5. Get one full loop working first. Player, collectibles, and one win or lose condition. Do not add anything else until that plays properly.
  6. Now replace the placeholders. Your character, your collectibles, your hazards, your world from Lesson 8.
  7. Rewrite the win and lose screens in your own words. "YOU WIN!" is the starter's voice, not yours.
  8. Tune the difficulty. Play it. Too easy? More hazards, or faster ones. Too hard? Fewer, or slower, or make your hitbox bigger.
  9. Add one thing the lesson did not ask for. A second mechanic, an ability, lives, a level. Something that is your idea.
  10. Play-test with a neighbor. Watch them play without helping them. Whatever confuses them is a real problem — go fix it.

Starter code

This code runs exactly as it is. Get it running first, then start changing it.

Main sketch tab (builds on everything from Lessons 2–8)
// Lesson 9 - Build Your Game
// Replace EVERYTHING marked CHANGE with your own choices!
import coxprogramming.processing.sprites.*;

MyCharacter player;
ArrayList<Blob> collectibles;  // things to collect for points
ArrayList<Blob> hazards;       // things to avoid
Block ground;
int score = 0;
boolean gameOver = false;
boolean playerWon = false;

void setup() {
  size(800, 600);
  restartGame();
}

void draw() {
  background(135, 206, 235);  // CHANGE: your sky/background color

  ground.drawSprite();

  if (!gameOver && !playerWon) {
    playGame();
  } else if (playerWon) {
    showWin();
  } else {
    showGameOver();
  }
}

void playGame() {
  // --- Collectibles ---
  for (int i = collectibles.size() - 1; i >= 0; i--) {
    Blob c = collectibles.get(i);
    c.move();
    c.drawSprite();
    if (player.collidesWith(c)) {
      collectibles.remove(i);
      score = score + 1;
    }
  }

  // --- Hazards ---
  for (Blob h : hazards) {
    h.move();
    h.drawSprite();
    if (player.collidesWith(h)) {
      gameOver = true;
    }
  }

  // --- Player ---
  player.followMouse();  // or keyboardControl() in keyPressed()
  player.drawSprite();

  // --- Win condition ---
  if (collectibles.size() == 0) {
    playerWon = true;
  }

  // --- HUD ---
  fill(50);
  textSize(22);
  text("Score: " + score, 20, 32);
}

void showWin() {
  textAlign(CENTER, CENTER);
  fill(80, 200, 100);
  textSize(54);
  text("YOU WIN!", width/2, height/2 - 30);
  fill(50);
  textSize(22);
  text("Score: " + score, width/2, height/2 + 18);
  text("Click to play again", width/2, height/2 + 52);
  textAlign(LEFT, TOP);
}

void showGameOver() {
  textAlign(CENTER, CENTER);
  fill(220, 60, 60);
  textSize(54);
  text("GAME OVER", width/2, height/2 - 30);
  fill(50);
  textSize(22);
  text("Score: " + score, width/2, height/2 + 18);
  text("Click to play again", width/2, height/2 + 52);
  textAlign(LEFT, TOP);
}

void mousePressed() {
  if (gameOver || playerWon) {
    restartGame();
  }
}

void restartGame() {
  score = 0;
  gameOver = false;
  playerWon = false;

  // CHANGE: move player to your preferred starting position
  player = new MyCharacter(this, width/2, height - 120);
  player.setVelocity(4, 0);

  // Ground
  ground = new Block(this, 0, height - 70, width, 70, color(80, 160, 60));

  // Collectibles - CHANGE: color, size, count, speed
  collectibles = new ArrayList<Blob>();
  for (int i = 0; i < 10; i++) {
    collectibles.add(new Blob(
      this, random(width), random(100, height - 120),
      random(10, 18), random(-2, 2), random(-1, 1),
      color(255, 220, 50)
    ));
  }

  // Hazards - CHANGE: color, count, speed (make them faster each wave if you want!)
  hazards = new ArrayList<Blob>();
  for (int i = 0; i < 5; i++) {
    hazards.add(new Blob(
      this, random(width), random(100, height - 120),
      random(15, 28), random(-3, 3), random(-3, 3),
      color(220, 60, 60)
    ));
  }
}

Make it yours

⭐ This is the part that matters most. Pick at least one and make it yours.

  • Theme it. Replace every placeholder color, name, and shape with your world — space, ocean, forest, city, dream, whatever it is.
  • Difficulty. Make hazards faster over time. Add more when a wave is cleared. Give the player 3 lives instead of instant death.
  • A second mechanic. A keyPressed() special ability — a speed burst, a shield, a projectile, a teleport.
  • Polish. A title screen before the game starts. Better draw order. Animated decorations. A high score that survives a restart.
  • A custom hazard. Write a new extends Blob tab for an enemy that behaves differently — one that chases the player using followMouse()-style logic is genuinely scary.

Finished early? Add a second level. When the player wins, instead of stopping, rebuild the world harder — more hazards, faster, a different background — and keep the score. That is restartGame() with a difficulty number, and it turns a demo into a game people want to keep playing.
