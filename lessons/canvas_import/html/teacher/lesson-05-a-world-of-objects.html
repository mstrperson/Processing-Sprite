Lesson 5

A World of Objects

One character is lonely. Time to fill the screen.

TimingOne period (~50 min)
New ideaLists and loops — handling many things at once
Builds onLesson 4 — your controllable character. Everything from Lessons 1–4 stays.
StandardStore many objects in an ArrayList and process them with both loop styles; use random() for variety.

Warm-up (~5 min)

How do you make your character move toward the mouse? Where exactly does that call go, and why there?

Direct instruction (~10 min)

Motivate the list before you show it

Start by writing coin1, coin2, coin3 on the board and asking what happens at twelve. Let the tedium land before you offer the fix.

This is the Lesson 5 slot in the arc precisely because students can now *feel* the pain of managing many things. Do not skip straight to the syntax.

ArrayList in three moves

"A list is like a bag — you can keep stuffing things in."

Declare, create, add. Show all three on the projector as three separate lines before combining them.

The two for loops — make this distinction explicit

This is the developer note on this lesson and it is the thing to get right.

Counting loop (in setup(), to CREATE): for (int i = 0; i < 10; i++). "i counts from 0 to 9 — we use it to repeat the add 10 times."

For-each loop (in draw(), to VISIT): for (Blob c : coins). "For each coin c in the list, move it and draw it."

Both use the word for, and in a broad sense both are count-controlled, but they *feel* different: one counts, one visits. Students mix them up constantly. Say the distinction out loud more than once, and use the words "create" and "visit" consistently.

Show the classic mistake on purpose

Write coins.drawSprite(); on the projector and run it. It will not compile.

"The bag is not a coin. You cannot ask the bag to draw itself." Then fix it with the loop. Seeing the error once beats a warning.

Custom sprite tab (optional, for motivated students)

Show the Cloud class — there is a working version in SceneExample/Cloud.pde in the examples folder.

"It is just like MyCharacter, but it draws cloud shapes instead." Same pattern from Lesson 2, no new concept. Students who want a richer world can write their own environment sprites.

Guided activity (~20 min)

  1. Put coin1, coin2, coin3 on the board. Ask what happens at twelve. Wait for the groan.
  2. Declare and create the list together. Run — nothing changes, because the list is empty. Name that.
  3. Add the counting loop in setup() together. Run — still nothing on screen. Ask why. (They exist, but nothing draws them.)
  4. Add the for-each loop in draw(). Run. The world appears. That two-step reveal is worth the extra minute.
  5. As a class, change 12 to 40, then to 3. Let them see the loop's power immediately.
  6. Deliberately move the player lines above the coin loop and run. Character vanishes. Move them back. That is draw order, and it sets up Lesson 8.
  7. Release for personalization: colors, counts, a second list, a mousePressed() spawner.

Common mistakes to watch for

  • coins.drawSprite() — calling a method on the whole list. The single most common error in this lesson.
  • Creating the list but never looping over it in draw(). The objects exist and are invisible. Students think the add failed.
  • Forgetting coins = new ArrayList<Blob>(); — a null pointer exception the moment they call .add().
  • Mixing the two loop forms: for (int i = 0; i < coins; i++) or for (Blob c : 12). Both come from not having the create/visit distinction yet.
  • Drawing the player before the coins, so the character is hidden.
  • Putting the counting loop in draw() — it adds 12 new coins every frame and the sketch grinds to a halt. Dramatic, and a good demo if it happens.

Wrap-up (~5 min)

Ask: What is the difference between the counting for loop and the for-each loop? When would you use each one?

Looking for: Counting loop: repeat something a set number of times — used to create. For-each loop: visit every item already in a list — used to move and draw. Accept any wording that separates "create" from "visit."

Teaching notes

  • Use the word "visit" for the for-each loop all period. It gives students language for a distinction they can otherwise only feel.
  • The Cloud class uses extends Blob, not extends Sprite, so it inherits collidesWith(). If students want clouds to be interactive obstacles in Lesson 7, this matters. Do not let a motivated student write extends Sprite.
  • Draw order gets a proper lesson in Lesson 8. Today just plant it.
  • Fast finishers should write a custom environment sprite rather than adding a third list of plain blobs — it reinforces Lesson 2 and pays off in Lesson 8.
  • Do not explain generics (<Blob>). It is "what kind of bag this is." That is enough.

Rubric reference (no points)

Standard
Store many objects in an ArrayList and process them with both loop styles; use random() for variety.
Getting StartedMy list of objects is not appearing. Next step: create things with a counting loop in setup() (for (int i ...)) and draw them with a for-each loop in draw() (for (Blob c : coins)). Check that you call drawSprite() on each item c, not on the whole list.
Got It WorkingMany objects appear and move — created in a counting loop, drawn in a for-each loop.
Made It Mine ⭐…and I tuned the world: changed the count, size, or speed, added a second list of a different kind (enemies, stars, bubbles), or spawned objects on click.
Went Beyond…and I wrote my own environment sprite class (like a Cloud) in a new tab and filled the world with it.

⭐ Made It Mine is the goal for everyone. “Went Beyond” has no fixed list — the examples are only starting points. Going somewhere the lesson did not ask for is the whole idea.
