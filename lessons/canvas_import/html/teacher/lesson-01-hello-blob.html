Lesson 1

Hello, Blob!

Run your first program and put something alive on the screen.

TimingOne period (~50 min)
New ideasetup() and draw() — and your first object
Builds onNothing. This is where we start.
StandardCreate and display a Blob, using setup()/draw() and RGB color.

Warm-up (~5 min)

Have you ever seen code before? What do you think it looks like? There is no wrong answer here.

Direct instruction (~10 min)

Tour the Processing IDE

Project the IDE. Point at the Run and Stop buttons, the text area, and the tab bar (they will need the tab bar in Lesson 2).

setup vs draw — use the metaphor

setup() = setting up the art table once. draw() = drawing a new page of a flipbook every fraction of a second.

Establish this now and reinforce it in every single lesson. Students should eventually predict without thinking: one-time things in setup(), repeating things in draw().

The import line

"This tells Processing we want to use the library's tools." That is the whole explanation. Do not go further.

Walk the Blob constructor parameter by parameter

  • this means "this sketch." Tell them to copy it exactly and never change it.
  • x and y place the center of the blob.
  • radius is how big — half the width.
  • color() takes three numbers: how much red, green, and blue.

Color and RGB — do not skip this

Spend real time here. Open Tools → Color Selector on the projector, pick a color, and show students where to read the R, G, and B values off the panel.

Most of the personalization in this lesson (and the enthusiasm for it) comes from students discovering they can have *any* color. Make sure every student knows the Color Selector exists before they start working.

Demonstrate background()

Change background(255) to background(0) live. White vs. black. Then, if you want a good moment, comment background() out entirely and add a moving blob later in Lesson 3 to show the smear.

Guided activity (~20 min)

  1. Everyone opens Processing and saves a new sketch as HelloBlob before typing anything. Saving first avoids the "where did my file go" problem later.
  2. Type the starter code together on the projector, line by line. Typing beats pasting here — they need to feel the syntax once.
  3. Everyone runs it. Circulate. The two failures you will see are a missing import line and a missing semicolon.
  4. Together: change the radius to 80, run, change to 15, run. Name what changed.
  5. Open the Color Selector as a class. Each student picks a color and puts their own RGB numbers in.
  6. Release them to move the blob, change the background, and try a second blob.

Common mistakes to watch for

  • Missing import line. By far the most common. The sketch will not compile and the error message does not point at the missing import.
  • Changing this to something else. Tell them up front it is off limits.
  • Putting myBlob = new Blob(...) inside draw() — it technically runs, but it rebuilds the object 60 times a second. Worth catching now.
  • Forgetting the semicolon at the end of a line.
  • Expecting color(255, 80, 80) to be quoted like text. It is three numbers, no quotes.

Wrap-up (~5 min)

Ask: What are the two magic functions, and when does each one run?

Looking for: setup() runs once at the start; draw() runs over and over, about 60 times a second. Students should be able to say this without prompting by the end of the period.

Teaching notes

  • The no-velocity constructor Blob(this, x, y, radius, color) is used deliberately. Velocity is Lesson 3.
  • Students will ask "how do I make it move?" That is exactly the reaction you want. Tell them that is next time.
  • If a student finishes very early, push them toward a scene made of several blobs rather than more fiddling with one.
  • Do not explain what an object *is* in any depth. They made one and it showed up. That is enough for today.

Rubric reference (no points)

Standard
Create and display a Blob, using setup()/draw() and RGB color.
Getting StartedMy sketch is not running yet, or no blob appears. Next step: check the very first line. A missing import coxprogramming.processing.sprites.*; is the number one reason a sketch will not run. Fix it and run again.
Got It WorkingMy sketch runs and a Blob appears on screen.
Made It Mine ⭐…and I deliberately changed at least one thing — color, size, position, or background — and I can say why I chose it.
Went Beyond…and I added a second blob with its own color and place, or arranged several blobs into a small scene of my own.

⭐ Made It Mine is the goal for everyone. “Went Beyond” has no fixed list — the examples are only starting points. Going somewhere the lesson did not ask for is the whole idea.
