Bonus Lesson A

Images

Swap your shapes for actual pictures.

TimingOne period (~50 min)
New ideaLoading and drawing image files
Builds onLesson 2 (extends Blob) and Lesson 4 (control). Nothing after this depends on it.
StandardAdd images via the data/ folder, display decorations with ImageSprite, and use a PImage inside an extends Blob character so collisions still work.

Warm-up (~5 min)

Have you played a game where the characters are pictures instead of shapes? Which one? Do you think that is hard to make happen?

Direct instruction (~10 min)

The data/ folder — do this together, slowly

Sketch → Show Sketch Folder, create a folder named data, drag an image in. Processing finds it automatically when the sketch runs.

This is the number one setup hurdle in the lesson. Walk through it on the projector and then wait until every student has actually done it before moving on.

Supported: PNG, JPG, GIF. Recommend PNG for the transparency.

ImageSprite for decorations

Three constructor forms: default 100×100, one number for a square, two numbers for width and height.

It has all the familiar methods: move(), setVelocity(), followMouse(), drawSprite().

It does not have collidesWith(). Scenery only. Say this now, because it is the whole point of the second half of the lesson.

Image inside an extends Blob character

Store a PImage field, load it in the constructor with p.loadImage(fileName), and in drawSprite() use pushStyle() / imageMode(CENTER) / image() / popStyle().

The Blob's radius is still the invisible collision circle. The picture is only what you see.

This is the right approach whenever a thing needs both a picture and collisions — which is every player, collectible, and hazard.

Transparency

PNG files can have transparent backgrounds, but only if they were saved that way. A PNG without transparency draws a white or colored rectangle behind the art, and this surprises students every time.

remove.bg is a free tool that strips backgrounds if a student is stuck with a bad file.

Guided activity (~20 min)

  1. Before class if possible: have students find or draw a small PNG. Options: a free sprite from opengameart.org, or a 32×32 character drawn in any paint program. Drawing their own is better if you have the time.
  2. Everyone opens Sketch → Show Sketch Folder and creates the data folder together. Wait for everyone.
  3. Everyone drags in their image and reads the filename out loud, exactly, including capitals.
  4. Do the ImageSprite decoration first. It is the simpler pattern and it gets a picture on screen within minutes, which is the motivating moment.
  5. Debug the inevitable white boxes and not-found errors as a group — the two causes are filename mismatch and missing transparency.
  6. Then introduce the image-inside-a-Blob pattern for their character, so collisions still work.
  7. Release for personalization: background images, more decorations, sizing.

Common mistakes to watch for

  • No data/ folder, or it is misnamed (Data, datas, or created in the wrong directory). The single biggest time sink.
  • Filename typos, including the extension and capitalisation. Hero.PNG is not hero.png.
  • PNG without transparency → a white rectangle around the character. Looks like a code bug; is not.
  • Forgetting imageMode(CENTER) → art offset down and right from the hitbox, so collisions feel broken.
  • Trying collidesWith() on an ImageSprite. It will not compile, and the error will not explain why.
  • Zipping the sketch without the data/ folder when submitting, so nothing runs. Say this out loud at collection time.
  • Huge source images (2000×2000) scaled to 60×60 — works, but slow and blurry. Small source art is better.

Wrap-up (~5 min)

Ask: Why can't you use collidesWith() on an ImageSprite? What do you do instead if you want an image character with collision detection?

Looking for: ImageSprite is not a Blob, so it has no collidesWith(). For a character that needs both a picture and collisions, put a PImage inside a class that extends Blob.

Teaching notes

  • This is enrichment. Nothing in the capstone requires it, and a student who skips it is not blocked.
  • The radius in super() is the hitbox and does not need to match the image exactly. A radius slightly smaller than the visible art feels fairer to play.
  • ImageSprite also has setRotation(angle) and rotate(amount) in radians — great for spinning decorations. Mention only if asked.
  • Fast finishers: two PImage fields toggled on a frame counter to fake animation. That is a natural bridge into Bonus Lesson C.
  • Sourcing art can eat the whole period. Have a small folder of ready-to-use PNGs available for students who cannot decide.

Rubric reference (no points)

Standard
Add images via the data/ folder, display decorations with ImageSprite, and use a PImage inside an extends Blob character so collisions still work.
Getting StartedMy image draws as a blank or colored box, or not at all. Next step: make sure the file is in the sketch's data/ folder (Sketch → Show Sketch Folder) and the filename matches exactly. A white box usually means the PNG has no transparency.
Got It WorkingMy own image appears in the sketch — as an ImageSprite decoration and/or as my character.
Made It Mine ⭐…and I themed the look with my own art — a character image plus decorations (or a background image), sized to fit.
Went Beyond…and I used an image inside an extends Blob character so collisions still work, added drifting image decorations, or swapped between two images to fake animation.

⭐ Made It Mine is the goal for everyone. “Went Beyond” has no fixed list — the examples are only starting points. Going somewhere the lesson did not ask for is the whole idea.
