Bonus Lesson C

Animate Your Character

Stop sliding a frozen drawing around. Make it move.

TimingOne period (~50 min)
New ideaA flipbook of poses — AnimatedSprite
Builds onLesson 2 — your MyCharacter drawing. You will reuse it directly.
StandardBuild a multi-frame animated character with AnimatedSprite and control its animation speed.

Warm-up (~5 min)

Have you ever made a flipbook in the corner of a notebook? How does a cartoon make a character walk? It is just drawings, shown fast. And remember from Lesson 1 — draw() is already a flipbook, drawing a new picture about 60 times a second.

Direct instruction (~10 min)

The flipbook idea — connect it to Lesson 1

Animation is a few still pictures, shown quickly in order, looping. Every student already understands this from notebook flipbooks.

Make the connection explicit: draw() is the flipbook engine they have had since Lesson 1. AnimatedSprite is the flipbook the engine flips through. Nothing new is happening underneath — they are just adding pages.

Name the two meanings of "frame" up front

A game frame is one run of draw() (~60/sec, from Lesson 3). An animation frame is one picture in the flipbook.

Say both out loud before showing setFrameRate(), or the number will make no sense to anyone.

The frame class — it is their Lesson 2 character

A frame is just a drawing, exactly like MyCharacter. The only addition is a pose number so the same class can draw a few variations.

Demonstrate: keep the body and eyes identical, change only the mouth between poses.

"Only change what should move — keep everything else identical, or it looks jittery." This is the single most important piece of art advice in the lesson.

Building the AnimatedSprite

AnimatedSprite.FromSprite(first).AddFrameSprite(next).AddFrameSprite(next).setFrameRate(8)

"FromSprite starts the flipbook, AddFrameSprite adds another page, setFrameRate sets the speed." Do not explain method chaining as a concept — just read it left to right.

CRUCIAL: create every frame at the SAME x, y, or the character visibly jumps when the page turns. Say this while you type it.

setFrameRate is a ratio, and it is backwards

It is game-frames-per-picture, not pictures-per-second. Smaller is faster. Minimum is 1. Default is 8 if never called.

Demo setFrameRate(4) and then setFrameRate(20) back to back on the projector. The direction only lands once they see it.

The Lesson 9 caveat — say it clearly

AnimatedSprite extends CompoundSprite, not Blob, so it has no collidesWith(). This is the one thing that will trip up a student who brings animation into their capstone.

The fix is distanceTo(otherSprite) < threshold. distanceTo() is inherited from Sprite and works between any two sprites.

Do not hide this. A student who discovers it mid-capstone with no warning loses a whole period.

Guided activity (~20 min)

  1. New tab MyCharacterFrame. Students paste in their own Lesson 2 character drawing, then rename the class and constructor.
  2. Add the int pose field and this.pose = pose; together.
  3. Make pose 0 and pose 1 differ in exactly one thing — the mouth. Do this as a class so everyone sees how small the difference should be.
  4. In the main tab, build the AnimatedSprite from two frames and run it. Watch it talk. This is the payoff moment.
  5. As a class, try setFrameRate(4), then setFrameRate(20). Ask which suits their character.
  6. Add a third pose together.
  7. Release to personalize: more poses, animating legs or arms, a second creature.
  8. If students are mid-capstone, spend the last ten minutes on the distanceTo() swap so they can actually use this in their game.

Common mistakes to watch for

  • Frames created at different x, y. The character teleports on every page turn. The most common and most confusing bug in this lesson.
  • Poses that differ too much. It reads as flickering, not animation. Push them to change one thing.
  • Expecting a bigger setFrameRate() to mean faster. It is the opposite.
  • Calling collidesWith() on an AnimatedSprite. It will not compile. Use distanceTo().
  • Forgetting this.pose = pose; in the constructor, so every frame draws pose 0 and nothing appears to animate.
  • Forgetting to rename the constructor when copying from MyCharacter — a constructor whose name does not match its class becomes a method that never runs.
  • Not calling drawSprite() in draw(), so the flipbook never advances.

Wrap-up (~5 min)

Ask: What is the difference between a game frame and an animation frame? What does setFrameRate(4) do compared to setFrameRate(20)?

Looking for: A game frame is one run of draw() (~60/sec). An animation frame is one picture in the flipbook. setFrameRate(4) holds each picture for 4 game frames (fast); setFrameRate(20) holds it for 20 (slow).

Teaching notes

  • Only the current frame is drawn, so the Blob's plain circle never appears — drawSprite() is overridden in MyCharacterFrame. The radius and color in super() are just carried along.
  • This lesson lands best during Lesson 9, when students are already looking at their character and wishing it felt alive.
  • Ties into Bonus A: a frame can be an ImageSprite, so a sprite sheet animates with exactly the same pattern — AnimatedSprite.FromSprite(new ImageSprite(this, x, y, "walk0.png")).AddFrameSprite(...).
  • Show the AnimatedSceneExample (File → Examples → Contributed Libraries → SpriteGame). Its clouds and sun are built with exactly this FromSprite/AddFrameSprite pattern, and seeing it in a finished scene is motivating.
  • Fast finishers: control the frame by hand instead of auto-advancing — nextFrame() or setFrameNumber(n) on a key press for a jump or attack pose.
  • Two poses is genuinely enough for a good result. Do not let students get stuck trying to draw eight.
